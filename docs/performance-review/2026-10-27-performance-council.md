# #15 性能大会：冻结结论与首批实施授权

状态：六位委员完成独立提案与交叉审议，主审于 2026-10-27 冻结。讨论期间源码保持 3512abb，无生产修改、构建或新压测。现仅授权本文首批工具、可选诊断与模型实施；未批准默认布局切换、旧卷迁移或直接开始正式 ABBA。

## 1. 性能定义

保留 timing schema 2 的 H4/H6「业务完成耗时」作为原主验收：H4 为持久逻辑会话写入并读回；H6 为每次新逻辑会话、写入、读回、关闭。H6 不代表新 TCP/TLS。追加 write SDK（含原 SDK 自动提交探针及 H6 首次 open，不是纯 SQL 提交）、issued→write return、read、close 和 fetch/headers/SDK 边界的独立统计，不改主分母，不相加分位数，不用 clone 消费结束当原始 EOF。

两轮完整 ABBA，每臂每场景至少 2000，原每轮 p99 ≤0.8A、每配对 p99 不回退、每配对 p50 ≤1.05A、每轮每场景 >100ms 比例严格下降及全部正确性门禁保持。A 的慢比例为零则下降不可证，不临时改阈值。原目标未通过不能用新指标改名为通过。当前 C1/50ms 只证明串行体验，不提供最大吞吐结论。

## 2. 测量规则

- 官方 v1.1.17 1872100 为主 A；前轮 856d470 仅为增量对照。新候选运行前冻结源码、二进制、SDK、helper、默认参数和最少样本数。
- 首先离线使用现有 32k raw 做逐阶段、逐深度窗口和全部尾点分析，不先重跑同一组数据。
- 诊断和正式数据分开；正式关闭服务诊断，仍承认客户端 observer/tee 开销。新诊断同时加到比较双方或在同一binary做 ON/OFF成本对照，不能给某一侧特殊待遇。打过诊断补丁的 A 必须有独立源码/binary 身份，不再标原1872100二进制；正式A仍用原冻结版本。
- 正式前必须有空间预算：整个32k至少12GiB可用，并依据实际增长计算「4GiB保留量 + 1.25×剩余预估增长」。每场景≥4GiB且used<90%边界门禁继续保留。当前4.4GiB不足，不启动正式运行。保留ENOSPC失败卷及全部raw；不在测量期间构建、清理、压缩或分析。
- 对历史累积机制，独立增加8192历史写+50warmup+2000timed的H4诊断；若触及session生命周期则另注册H6历史生成方式，不把持久session prelude当作8192次新session。
- 预注册本轮最多进入一个新产品候选、一个正式 campaign，正式固定两轮、每臂每场景 2000 次；数值有利或不利均不提前停止或追加追样。SQL/Unknown、证据、身份或资源硬门禁失败时立即停止并保留，不拼臂、不丢尾、不重试SQL。基础设施失败后若重新启动，须另起目录、记录原因及新计划，不将旧样本拼入。时序自相关和历史增长不被bootstrap自动消除。

## 3. 归因结论与实施优先级

前轮候选100个业务>100ms样本中95个最长action是write、94个最长可观测片段是write dispatch→headers；这个区间包含网络与服务器，不能命名为fsync。R2/H4 write SDK p99也仅下降7.5%、write>100从15增至27。优化优先级仍在写路径，但读/close不能被排除。

首批实施顺序：

1. 建立可复核的离线分层报告与全阶段成功/失败账本，按 setup/prelude/warmup/timed 分账，列出 planned/issued/写ACK/精确读回/closeACK/完整成功/Unknown，严格验证身份、序列和字段缺失；不修改 SDK 热路径。写ACK后读失败仍是业务失败。
2. 补本地跨层ID边：Worker request → Authority request → publication/group。使用现有ID，不改变RPC wire，不把墙钟近似作为精确桥。默认关闭；链接完整性与阶段覆盖完整性分开记录，未完成/丢失不得标完整。本批可只交付精确链接且明确 incomplete，不为凑完整标志更改 wire。跨进程单调时钟不可相减，父子/并行阶段不可直接相加。
3. Go journal/audit复用既有内存中的 request ID，按 batch/revision 给出queue、encode、write/sync、checkpoint/compaction的边界。仅加诊断载体，不改StateStore公共接口或持久record字段；一批成本只记录一次，成员只记等待。维护/多owner显式标识，不猜唯一request。只补诊断，不改变审计是否必需、ACK顺序及持久化条件，不记录SQL、payload或密钥。
4. 有界收据选择窗口仅作为结构模型实验：保留数量、oldest anchor、canonical64批次、全部staged页。先评估Page算法生成页/字节、CPU成本、2.5k/10k/50k历史及不利seed；这些不是完整Authority发布对象或物理Sync实测，后者需真实路径验证。此刻没有证据支持额外20%结构收益；未显示稳定机制收益则不改生产selector。

上述是可实施任务，不是性能收益承诺。每个任务由不同subagent实现和复核，代码评审与性能判断分开。

## 4. 结构性路线与明确不做的捷径

local pack是当前已有实现证据的主要结构路线之一，但A也已有它。真实receipt body经Authority转成opaque `authority/blobs`，现有pack对它们逐项隔离，不能把50个receipt页直接换算为2个pack。必须先按实际物理key/family/大小分类，估计并验证净收益；再决定是否做同binary OFF/ON的独立机制实验，不能作为新代码收益或默认修复。当前非空legacy卷拒绝入场，无在线迁移；默认启用/旧卷转换、旧handle/多进程、备份、回收、读放大及故障路径必须另过设计门禁。本轮不直接开启默认pack，不偷偷给B开flag。

不改64+1重放约定或删除旧validator要求的中间页。不通过减小归档批次、固定相位对齐、少验证、少reader pin/GC、提前ACK、免审计或SQL重试获取数字。减少物理同步次数只有在相同durability proof成立时才允许。

## 5. 实施后的阶段门禁

- 工具/诊断必须先通过离线损坏输入、ID歧义、丢事件、嵌套scope及故障语义测试；默认关闭时不改变业务结果。
- 诊断能解释同一请求及保留未覆盖部分之后，才选一个主要优化假设，做独立小规模机制验证；不能同时改变布局、缓存、SDK和并发。
- 只有正确性、机制证据、资源预算均通过，才冻结新候选并启动完整正式ABBA。无合格候选或资源不足则明确停在该阶段，保留已完成工具/模型交付，不冒充性能修复。
- M4/OrbStack真实v6卷和原脚本/JSON仍未取得，目标环境验证独立标为未验证；本机结论不能外推。

## 6. 会议表决与任务分工

六位委员均无未关闭P0/P1；指标、测量、归因、存储、运行时、独立反方均同意先实施上述有限范围。已吸收并关闭的修订：原体验门槛与write口径、固定轮数/硬停止区别、诊断A身份、opaque pack范围、模型与真实发布区别、有限归因仍incomplete。
