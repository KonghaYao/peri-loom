# 2026-10-17 预取落地后的九臂重复观测（p1–p9）

结论先行：这是一组**探索性单次观测**，不是 A/B、不构成性能或容量证据。九臂自报的
`performance` 与 `capacity` 恒为 `NOT MEASURED`；除 p1 外 `correctness` 全是 `INCOMPLETE`
（4000 次操作的预算/时长没跑完整份 manifest，属预期，不是数据缺失）。

**这组臂不测预取。** 它们只做「开 SQL session → 按 4000 次预算发查询 → 关 session」，
数据库在整臂 45–60 s 内保持加载（`PERI_WORKER_DB_IDLE_UNLOAD_MS` 默认 60 s），
一次冷回放都没发生。所以它回答的是「预取落地后的构建在稳态查询与准入上有没有变坏/崩溃」，
回答不了「预取让冷开快了多少」。冷开本身由同一栈上的冷回放循环与 idle-reopen 探针观测（见第 4 节）。

## 3. 为什么不能把这当成「预取更快」的证据

这不是 A/B，至少有四层混淆：

1. **栈与数据不同**：w 轮跑在旧栈（旧 run 目录）上，p 轮跑在新栈上；旧栈在被测前已经历过
   更长的写入历史（前面几轮的导入与臂），WAL/索引/镜像都更大。
2. **二进制不同**：p 轮是新构建；w 轮是旧构建。差异不止预取一处。
3. **时间与主机负载不同**：p 轮 load average 3.05–4.66，且有并发会话在跑；两轮不是交错执行。
4. **臂本身不触发冷回放**（见开头）：预取只在冷开时工作，而臂里的数据库一直保持加载。

因此上表只能读出两件事：**没有出现崩溃、Unknown、超时或校验不一致**；
**p1 把 4000 次操作的 manifest 跑完整了（0 missing，ORACLE_VERIFIED），w1 没有（518 missing）**。
后者是一次单次观测，不能外推成「低并发下变快 15%」——要得到那个结论至少需要同一栈、同一数据集、
交错重复的 A/B（见第 6 节）。

## 4. 同一栈上的冷开与重开观测（行为观测，不是延迟结论）

- **冷回放循环**（p 臂之前，3 轮）：每轮空闲 65 s 触发卸载，再冷开。三轮 `open: ok`，
  open 2.001 / 1.989 / 1.987 s，close 0.014–0.033 s；进程峰值 RSS 单进程
  207,104 / 207,120 / 212,416 KB，栈总和峰值 441,888 / 417,952 / 440,176 KB。
- **故障恢复探针**（p7 过载臂之后）：`open: ok` 0.018 s，close 0.012 s。
- **30 s 空闲重开探针**（九臂全部结束后）：`open: ok` 0.021 s，close 0.013 s——
  30 s 小于 60 s 的卸载 TTL，所以这是**温热**打开，不是冷开。

**不可说**：不能拿 2.0 s 的冷开与旧实现那次 5.3–7.6 s 的单次观测（见
[冷加载停摆](./2026-10-17-open-load-stall.md) §4）相比。两者栈、数据、负载、时间都不同，
而且旧实现那几次观测已被回退，数字不可转移。冷开要成为证据，需要同一栈上「卸载→冷开」的
交错重复测量，并同时记录 WAL 长度、chunk 数与进程 RSS。

## 5. 顺带观测到的平台准入行为（与预取无关，两轮一致）

- `sessions=16/32`、`16/100`：第 17 个 session 起返回 `quota_exceeded`（`open_failures` 从
  index 16 开始），两轮完全一致。
- 高并发臂的拒绝原因桶是 `concurrency_limit` 与 `session_limit`；`unknown=0`，
  即没有出现「结果未知」的请求——本次没有任何自动重放。
- 所有臂 `mismatched=0`（读回值与 oracle 一致），失败都是「没轮到/没被受理」，
  不是「读到了错的值」。

## 6. 要得到可宣称的加速证据，还需要什么

1. 同一个栈、同一份数据集，**交错**跑旧/新两个二进制（A/B/A/B…），而不是先后两轮；
2. 冷开专项：每轮显式等待卸载（> 60 s idle 或管理接口），记录 WAL 字节数、chunk 数、
   索引条目数与实测 RSS，重复 ≥ 5 次，报告分布与区间；
3. 固定到达率、闭环与开环分开，避免客户端变慢自动降载掩盖排队；
4. 预取窗口/预算作为自变量（默认 160 MiB、1、8 个单位各跑一档），证明窗口确实影响冷开
   的 Authority 调用次数与墙钟；
5. 在这些做完之前，任何「快 N 倍」都不成立；本文与两份设计文档都保持
   `performance = NOT MEASURED`、`capacity = NOT MEASURED`。
