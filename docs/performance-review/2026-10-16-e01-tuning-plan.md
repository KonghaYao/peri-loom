# E01 对照调优方案（分阶段、先小测后放大）

日期：2026-10-16。基线提交：`80d3fcdb74372617de52d0e047298773fc25f44c`。
本方案只改本技能（客户端侧基准工具）；**任何平台业务代码改动需先由主线程决策**。
不把关闭 TLS/审计/持久化、放宽配额或超时当作优化；不绕公开 URL+token；不做 SQL 自动重试。

## 0. 基线事实与对齐缺口

| 事实（100k，同 config/manifest/SQL） | 值 |
| --- | --- |
| platform C1 | 32.0 成功 ops/s；各族成功 p50 25.98–28.03ms、p99 57.25–90.86ms |
| native C1（同计划，本地持久库，sync=full） | 584.2 成功 ops/s；各族 p50 0.038–0.947ms、p99 1.61–11.74ms |
| platform C16/C100 | 83–85% 请求 `quota_exceeded`；C100 仅准入 16 会话 |
| platform 导入 | 100k 成功（10k 行/提交，COMMIT 合计 18.8s）；8M 在 570k 因 COMMIT `sql_timeout` 中止 |

**测量对齐缺口（必须先修，否则比值不可信）**：①事务/批次不同（native 单事务 vs platform 每 10k 行提交）；
②连接策略不同（原生进程内 vs 每请求新建 TLS 连接）；③未做资源冻结（非同步同资源 A/B）；
④样本窗口短（C1 ≈6.9s）；⑤深度受限（570k 档仅 0.13% 组深度）。

## 1. 假设 A（首选，低风险）：每请求新建连接是平台 C1 延迟主因

- **证据**：客户端每请求经 `urllib` 新建连接（无连接池）；公开 Go SDK `transport.DisableKeepAlives = true`。
  平台侧各族 p50 集中在 26–28ms、族间差 <15% → 更像固定传输成本而非数据成本。
- **待查证（只读源码）**：生产 SDK/网关是否支持标准 keep-alive；客户端复用连接是否改变会话/准入语义。
- **作用边界**：纯客户端（`scripts/platform_client.py`、`run_platform_queries.py`），不改平台、不改服务端配置。
- **最小改动**：新增 `--connection-mode {per-request,reuse}`（默认 `per-request`，保持既有语义），
  复用模式下按会话维护 `http.client.HTTPSConnection`，每会话串行独占（与现有多会话模型一致）。
- **正确性检查**：同一 manifest 全量比对仍须 `ORACLE_VERIFIED`；错误/拒绝/Unknown 计数不得增加。
- **性能检查**：同计划 C1 与"实际可准入并发"各 ≥3 轮、交替顺序，比较中位成功吞吐与 p99。
- **回滚**：开关默认关闭；删除开关即回到基线行为。
- **候选突破阈值**：中位成功吞吐提升 ≥20% 或关键族 p99 显著下降，且在 ≥3 轮交替中稳定超出噪声带；
  未达则记录为"无突破"，不得判 PASS。

## 2. 假设 B：Gateway 固定成本（同步审计 / operation 日志 / 请求校验）

- **证据**：C1 固定 ~26ms；族间无差异；需只读源码确认每请求是否触发审计落盘与 operation 记录。
- **作用边界**：平台侧，**只诊断不改**；若确认是固定成本，产出结构化证据交主线程决策。
- **候选文件（只读）**：`prototypes/v1/platform/gateway*.go`、审计相关文件（并行工作流正在改，仅读不写）。
- **检查/阈值**：不以降低审计或持久性为手段；若结论是"不可优化"，如实记录。

## 3. 假设 C：16 会话/请求 quota 来源

- **证据**：C100 仅准入 16 会话；诊断 C100 拒绝码 `quota_exceeded`。
- **做法**：只读定位该上限来自哪级配置（项目 quota vs worker 并发 vs 请求预算），产出结论与影响面。
- **禁止**：本轮不改配额；若提高需用户单独批准（会改变部署语义）。

## 4. 假设 D：提交期限与持久化成本（影响 8M 达成）

- **证据**：570k 处 COMMIT `sql_timeout`；100k 时 10 次提交共 18.8s（≈1.9s/次且随事务增长）。
- **候选改动（客户端侧）**：更小提交批次（1k–2k 行）+ 可跨事务续跑且可回读校验的导入流程；
  native 侧以相同提交粒度重跑以保持可比。
- **不做**：不调平台 `sql_max_duration_ms`/`dev_sql_timeout_seconds`。
- **检查**：planned/attempted/insert-ack/commit-ack/readback 分列且一致；中断不自动恢复/重放。

## 5. 小测协议（先小后大）

1. 规模：100k（回读核实），同 config/manifest/SQL。
2. 并发：C1 + 实际可准入并发（当前 16）；C100 仅作拒绝率观察，不并入比值。
3. ≥3 轮、交替顺序（A/B/A…），每轮采完整成功工作量；报告每轮与中位数、噪声带。
4. native 同数据、同提交粒度、同连接数（原生仅进程内连接），并注明资源非冻结。
5. 升级条件：仅在"候选突破"稳定复现后，才升到 570k/8M；否则停在 100k 记录无突破。
