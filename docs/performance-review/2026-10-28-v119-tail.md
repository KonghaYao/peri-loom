## 本轮改动

1. bucketed pin 索引更新先在内存中保留变更草稿，只持久化最终仍可达的页面；合并已经读取的相邻叶子，不为尝试合并额外读取兄弟节点。该路径在本版本默认启用。
2. 新增默认关闭的 Go journal 入队前 14 段耗时与 namespace 等待归因，并校验 caller 唯一性；新增 journal/audit batch、audit checkpoint 与 compaction 诊断。
3. 新增默认关闭的 Rust 物理存储计数、group shape、Worker→Authority→publication 本地 ID 链接及确定性测试 ID；新增离线分阶段/失败账本工具 `scripts/perf-reliability/issue15/`。

持久化屏障、ACK 时机、SQL 执行次数及 SDK 行为保持原有设计；没有提前 ACK 或自动重试 SQL。诊断开关默认关闭，默认路径不改变业务结果。WAL 65→64 和 authority receipt locality 两个实验未进入此候选。

## 交付方两轮 ABBA

同一 Linux x86_64 环境、默认关闭各实验/诊断开关，完成两轮 ABBA；每臂每场景 H4/H6 各 2000 次 timed，共 32,000 次。变化为 B/A−1，负数表示降低。

| 轮次 | 场景 | 业务 p99 变化 | >100ms 比例 |
|---|---|---:|---|
| 1 | H4 | −19.58% | 下降 |
| 1 | H6 | −18.29% | 下降 |
| 2 | H4 | −20.25% | 下降 |
| 2 | H6 | −26.13% | 下降 |

所有配对 p50 在 5% 容差内；第一轮 H6 有一对 p99 回退约 4.99%。预先冻结的门槛要求每轮 H4/H6 均至少降低 20%，且所有配对 p99 不回退。因此整体 **FAIL**：本轮没有把新指标改名为通过，也不宣称已解决用户报告的 M4/OrbStack 写长尾。

## 归因进展与仍未解决的原因

交付方诊断中 10 个超过 100ms 的慢请求均精确关联到 65 条 WAL 回执归档，主要时间处于 native 写入路径；这仍不是完整的跨层关键路径证明。该结论未在 Apple M4 / OrbStack 环境复现，也未证明断电恢复。

## 已知边界

- 本版本不宣称完整 Hrana 兼容；E1（HTTP v3 写 cursor abort 无可确认回滚证明）仍是显式 known-gap。
- 不提供容量、公平性或生产可用性结论；干净重启与已确认 SQL 恢复的既有边界不变。
- 诊断记录可能缺失、丢事件或被截断，缺失的证据不得按零成本处理；不同进程的墙钟不可相减，父子/并行阶段不可直接相加。
