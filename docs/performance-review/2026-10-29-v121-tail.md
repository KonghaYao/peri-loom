# v1.1.21 issue 15 候选：Hrana 成功结果交接与路由摘要复用

状态：**preview；交付裁定为保留机制候选，业务性能验收 HOLD**。本版本不是 #15 的修复，
也不是 sqld 追平声明。以下性能数字来自第七轮交付报告，本次发布没有在本地重跑性能或容量测试。

## 改动

- Gateway 在操作结算与持久化审计之后，把成功的 `json.RawMessage` 直接交接给进程内 Hrana
  接收器，省去外层结果包装、Recorder 正文复制与再次解包。结果仍按原字节预算复制并 compact，
  不是零拷贝。
- 错误、202、stream 与非 `json.RawMessage` 结果保留原路径。鉴权、准入、fencing、Unknown、
  审计、关闭确认与 SQL 执行次数均未改变；外部 REST 编码未改。
- 承接上一轮已接受的 Rust 祖先前缀摘要复用；新增验证覆盖叶页形状、完整祖先路径和坏祖先拒绝。
- 新增固定 serverless 1.4.1 的 all/close 诊断器、完整结果摘要、隐藏重试阻断、close ACK 与
  截断空结果检查，以及独立分析器。

## 交付报告中的结果

机制微基准（固定同一二进制、`GOMAXPROCS=1`、500ms 窗口、两轮 ABBA）显示局部结果转换耗时
下降 57.8%–72.7%，分配字节约减半，`allocs/op` 从 33/35 降到 12；这不是业务 p99，也不是
CPU 采样。

四组合成业务（每侧每场景 N=400）没有稳定改善：

- 0 行 p50 下降 3.1%，1 行 p50 上升 6.4%，20 行 p50 上升 1.1%，8,625 窄行 p50 下降 1.4%。
- 20 行 p99 上升 16.3%，8,625 窄行 p99 上升 11.6%；窄行两对交错比较的 p99 都更差。
- 小查询 p50 仍约为 sqld 的 2.78–2.90 倍；窄行代理中 peri 快于 sqld，但基线本身更快，
  不能归因于本轮改动。

因此本轮不能宣称业务提速、尾延迟改善或 sqld 追平；正式 sqld 追平 gate 与 issue 15 真实业务
均未验收。交付报告记录 `formal_pass`、`recovery_proven`、`capacity_proven` 均为 false。
