# v1.1.20 issue 15 候选：叶页编码复用与 guarded read 归因

状态：**preview，不是 #15 的修复版本**。本轮两轮 ABBA 已完成，但完整验收未通过：
第 1 轮 H4/H6 均达到 20% 门槛，第 2 轮两个场景都未达到，且第 2 轮 H4 增加了慢请求。
本版本是性能机制候选，不能宣称已解决 M4/OrbStack 写长尾。

## 来源与应用

- 交付源码冻结在 `2f10fc79b4a0d7bffd72eb2ba6b5fa59591dd938`，上一轮为
  `04c5e91ecab503655324a4a86b9f6566d2e3e5de`。
- 交付树共 1225 个文件；相对 v1.1.19 有 3 个新增文件和 9 个内容不同的文件。
  `Cargo.toml`/`Cargo.lock`、`platform/README.md` 与离线分析工具保留本仓库的版本、
  发布说明和 macOS 路径修复；`authority.rs` 的差异只是 rustfmt 模块排序，未采用交付侧副本。
- 本版本按文件级合并，不回退 v1.1.18/v1.1.19 的页缓存、回执选择、折叠索引和诊断改动。

## 改动

- bucketed pin-index 更新复用已经完成 16 KiB 大小检查的叶页 JSON 编码，避免同一叶页
  再次序列化。编码复用保持相同的序列化字节、hash、页边界和发布顺序；测试开关只用于
  与旧路径逐字节比较，不参与生产选择。
- guarded read 补齐 Go 包装层、native RPC 与 worker 阶段的耗时归因，默认关闭。
- 新增持久化回执重放契约测试，覆盖中间页与 reader pin 不被省略。
- 不改变持久化格式、barrier、ACK 顺序、重试策略或响应边界。

## 两轮 ABBA 结果

测试环境为同一 Linux x86_64，实验与诊断开关默认关闭。结果只属于该次运行。

| 场景 | 第 1 轮业务 p99 | 第 2 轮业务 p99 | 每轮均 ≥20% |
|---|---:|---:|---|
| H4 | −34.47% | −12.49% | 否 |
| H6 | −42.89% | −11.47% | 否 |

- 第 2 轮 H4 慢请求从 16 增至 18；B2/A2 组对 p99 回退 19.04%，B1/A1 组对 p50 回退 6.04%。
- 第 2 轮 H6 的 B2/A2 组对 p99 回退 5.75%。
- 归因修复本身不构成性能收益；第 2 轮的回归也不能用本轮的编码复用解释为已解决。
