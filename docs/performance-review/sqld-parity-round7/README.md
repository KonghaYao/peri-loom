# 第七轮：结果交接优化与 sqld 同机诊断

2026-10-29。**裁决：保留可评审的机制优化候选；业务性能验收 HOLD。**

本轮已实现 Hrana 内部成功结果交接，并承接上轮已接受的 Rust 祖先前缀摘要复用。局部结果转换耗时下降约58%–73%、分配字节约减半，但完整业务没有稳定改善：小查询 p50 仍为 sqld 的约2.8–2.9倍，20行与8,625窄行 p99 上升。不能把微基准收益宣传为业务提速，也不能宣布 sqld 追平。

## 已实现的改动

- Gateway 在原有操作结算和持久化审计之后，向进程内 Hrana 接收器交接成功 `json.RawMessage`，省去外层结果包装、Recorder正文复制和再次解包。仍复制并 compact 结果，保持原有编码与结果字节预算；不是零拷贝。
- 错误、202、stream、非 RawMessage 保留原路径。鉴权、准入、fencing、Unknown、审计、关闭确认和SQL执行次数均未改变。外部 REST 编码未改。
- 上轮 Rust 路由摘要复用原样承接；A/B共用同一原生二进制，本轮不重复计算其收益。
- 新增固定 serverless 1.4.1 的完整 all/close 诊断器、完整结果摘要、隐藏重试阻断、close ACK和截断空结果检查，以及独立分析器。

Go 候选提交 `3eb267f`；R6承接 `57ce8b8`；最终测量源码 `c7680fdf338b181594c77792264c08ac1085fd62`。之后仅增加报告及分析器交付文件。

## 完整业务实测

仅使用第三轮通过全部校验的 `comparison-final`。顺序 A→S→B→B→S→A；A为主干Go基线加同一R6原生运行时，B为候选，S为固定sqld。每腿每场景预热20次、计时200次；合并每侧每场景N=400。4800个计时读取和480个预热全部成功；9600个计时HTTP请求、4800个计时close ACK，错误、Unknown、重试和未确认close均为0。建表与导入另记，不计入读取。

### 业务 p99 到底是什么

客户端单调时钟从开始创建**逻辑SDK连接**，经过 `all()` 完整读取、传输、解码与物化全部结果，到必要的 `close()` Promise 返回。实际HTTP close ACK另外强制验证，SDK吞掉close错误也不算成功。逻辑新连接不等于新TCP/TLS握手。

观察器证据解析、结果摘要和写文件不计入业务钟；clone/tee正文收集仍与业务重叠。原始记录同时保留 sdk_completed、evidence_settled 和 validation_completed。

每侧每场景400条排序后第396条就是本表p99；单腿200条取第198条。它不是平均、最大值或最慢1%的平均；也不能把read p99与close p99相加。大结果的 >100ms 计数是描述值，不是复用H4/H6的短请求SLO。

## 目标与验收状态

- 原五场景p50≤1.5×配对sqld的门槛不变，本轮未验收。
- 六项真实业务按已接受计划先达到sqld的1.1×，再努力达到1.0×；容量研发目标为同SLO、同资源下≥90% sqld，本轮未测容量。
- H4/H6原要求（两轮ABBA、每侧每场景2000计时样本、p99改善≥20%、>100ms比例下降、p50不明显退步）不变，本轮未重跑此gate。

## 条件与限制

Linux x86_64，8 CPU cgroup额度、8GiB内存，单并发顺序客户端、最小50ms节拍；不是吞吐测试。每腿独立新数据库，固定8625行、每行32字节内容；实际测窄列。数据整体摘要 `48b816cbab91118bde7a8d911fccc933339c72d75e3616dcd0d3bb4c5cf2429d`。

固定serverless 1.4.1与lock；sqld官方0.24.32 (`40c272de...`)，运行查询确认`PRAGMA synchronous=1`、`journal_mode=wal`。sqld无鉴权、默认relaxed；peri保留token鉴权、默认配额、审计与持久化，未为了对齐去弱化合同。均为loopback明文，未运行TLS轨。因此这些服务合同和部署差异不满足正式可比性验收。

A/B共享native SHA256 `5875b5969f9236d424c625f9dc81d8284df763d492b974d7741392a0f15a78f1`。A Go SHA `87be5217ab97fb7db98780a5cebca90ad36089417f042bdee3e06ce830607b5c`；B Go SHA `b9338d075ebe95cf3e44876e5f2faca9e4db5e27e243436c5a7049a0298c9cc7`。Turso固定 `24a3a4609683b73935888f8bc30b47727d100aa8`。没有改SDK版本、结果集合、权限、额度或错误重试策略。

当前环境不允许AF_UNIX。端到端仅在外部诊断wrapper中省略维护socket启动，产品代码不改；正常分阶段关闭保留。这不证明恢复、故障切换或完整部署合同。
