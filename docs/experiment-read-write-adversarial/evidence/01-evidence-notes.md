# 实验 01 证据边界补充

本说明在独立验证后补充，只修订解释与元数据，没有重跑实验或改写原始日志、测量结果及锁文件。

## Rust 依赖补丁版差异

读取两个已存在的锁文件确认：

| 依赖 | 冻结项目 `prototypes/v1/Cargo.lock` | 归档 harness `01-rust-Cargo.lock` |
| --- | --- | --- |
| serde | 1.0.229 | 1.0.229 |
| serde_json | 1.0.151 | 1.0.154 |

harness 创建独立 Cargo 项目，首次执行 `cargo build --release --offline` 由本地缓存解析到 1.0.154；它没有先复制冻结项目的锁文件。归档的运行脚本后来增加了优先复制 harness 锁文件的步骤，以固定此微测版本，并未将其变成生产版本。

RpcResponse 的源码结构从冻结项目截取，校验规则按冻结客户端复制，但实际执行的 JSON 实现不是冻结生产锁文件原样版本。所有解析耗时、分配数字及 25 个契约用例只证明 serde_json 1.0.154 下该 harness 的结果。不能直接归为生产 1.0.151 parser 的精确成本，也不能据此保证跨补丁版本行为相同。没有进行跨版本 A/B。另有 feature 差异：业务启用 serde_json `raw_value`，独立 harness 未启用。

## Go 测试源码归档时间线

1. 最初新增只含 1 条/32 条小记录的测试文件并运行六轮；`01-go-raw.log` 中校验日志引用 `adversarial_rw01_test.go:78`。
2. 收到补充接近字节上限场景的要求后，修改同一个测试文件：增加 `strings` import 一行；在 `adversarialBatch` 增加受 `RW01_FULL_ONLY` 控制的大 `remove` 字符串设置一行；将直接遍历 `[1,32]` 改为 counts 变量及条件选择，共净增两行。合计净增四行，归档文件校验输出位于第 82 行。
3. 随后以 `RW01_FULL_ONLY=1` 运行另六轮，记录在 `01-go-full-raw.log`。最终 `01-go-bench_test.go` 是包含两类场景选择的版本；不设置 FULL_ONLY 可复现小记录场景，设置后可复现容量边界场景。

以上改动和顺序依据本次执行记录。所记改动均位于 import 或基准计时前的输入/场景选择；执行记录没有修改两臂计时循环或业务方法。**原始小记录版本没有单独归档源码、测试二进制及其 hash，也未按每轮采集构建身份**，因此最终文件与早期日志之间仍有审计缺口。没有重建或伪造一份“当时原版”源码来填补它；这里的时间线不等于独立二进制身份凭证。

## 文件系统类型

原环境收集里的 `df -T <lab>` 没有留下可用的文件系统类型信息，收集器也未保存退出码。最初元数据中的“local APFS temporary files”是未经验证的环境推断，现已改为“local temporary files, filesystem type unverified”。本实验确认使用了本地临时文件和真实 `os.File.Sync` 调用，不能声称已验证该卷为 APFS，也未做不同文件系统之间的性能对比。
