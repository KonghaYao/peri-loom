# 第 9 轮预注册：当前机器的有限探索性 SQL 微压测（2026-10-15）

## 研究问题与边界

在用户明确允许当前机器做**小规模**验证后，针对已经拥有且回环隔离的 RustFS，观察本机 debug/Rust 原生 SQL 路径上的逐次确认写入和点读耗时、第一次正确性错误及重启新缓存读回。**不使用正式 stress harness，不运行 challenger 场景，不把 P4/S3 子集当 P0–P6 联合 PASS**。本机同时运行其他进程，结果不能当独占机器、发行版本、网关 TLS、并发容量或 SpaceX 商用性能指标。事前没有业务目标 SLO；仅报实测样本与边界，不报告达标百分比或性能改善。

## 预先固定参数与停止条件

- 在 `trial-ground` 所有且已经运行的专属 Compose project、回环对象存储、512 MiB/0.5 CPU/64 PID 限额下，新建并保留**仅本次测试**使用的随机桶和唯一 namespace/DB；不接触试炼场基础桶、先前 9 个测试桶或其他业务服务。每次只有 1 个本地 Rust debug 进程的 1 个数据库，无并发请求、无 SQL 层自动重试或后台发压；沿用当前测试夹具 S3 客户端内置 `retries=2`，计时包含可能发生的 S3 重试，不能冒充单次服务器处理时间。
- 在操作前写入私有 0600 意图（源码 Git HEAD、脏状态摘要、目标容器/镜像、端口、上限与样本设计），证据目录 0700，日志和逐操作 JSONL 为 0600。16 次**串行单行事务**（ID 1–16、amount=ID）、64 次**串行定值点读**（依次轮流查询 ID 1–16，每次核对 amount），每次由单调时钟测量调用返回时延；设置 90 秒整体主动预算，启动时先预留本机资源空间并核查独占容器标签、回环端口、卷、运行态与配额。
- 写入的唯一业务 ID、金额与期望行数/合计事前确定；只把确定返回成功的写计为已确认。任一 SQL、网络、对象存储、校验、资源/归属失配或未确认结果立即停止后续操作，不重试，保留桶、cache、日志、异常与 Unknown 待核；测试失败不得为凑绿色修改门槛覆盖第一次结果。
- 完成有限负载后丢弃本次活跃实例、以新的空缓存与数据库对象读取行数/金额/完整 ledger 并执行 `PRAGMA integrity_check`；外部审阅者从预期 ID/金额和留存 JSONL 复算，而不使用数据库输出来定义预期集合。客观记录 16/64 个原始纳秒样本、成功率、nearest-rank p50/p95/p99/max（小样本提示）、冷读回耗时、结束时单点资源快照和任何缺失。没有按请求边界采样的指标填 `NOT MEASURED`。
- 不预置商用 ACK/s/p99 门槛；本轮**不允许**把 16/64 样本外推为饱和容量、多个租户公平性、对象存储放大、网关时延或稳定尾延迟。若所有正确性及证据检查成功，仅可称“本机有限探索性 SQL 微压测数据可复核”；仍须在冻结版本/专用机器/SLO/联合门禁之后另做正式 R1/R2/R3。

## 独立复核

执行者保存首次运行全部私有原始证据；独立验证者只读复算样本数、单位、会计关系、ledger/冷读回、目录权限、当前桶目录与运行身份，并反证任何把用例 wall time 或单点 CPU 当 SQL p99/峰值的表述。若原始数据不全或持久性/身份不能独立证明，指标标 `PARTIAL`/`NOT MEASURED` 而不是 PASS。
