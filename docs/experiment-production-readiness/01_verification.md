# 验证报告 1：本地卷异常中断后原卷重启

## 总体评估：PARTIAL

报告的窄结论可信：被测容器在异常终止后使用原卷重启，最终以退出码 1 停止，未恢复 SQL 服务。它未满足计划中的异常中断成功标准；正常 TERM 对照、替代卷以及更广的灾难恢复和高可用目标仍待实验。此评估只审查已有实验和只读证据，未重跑容器。

## 逐维度评估

### 数据完整性：PARTIAL

- 可独立核对的证据：镜像引用的本地 ID 为 `sha256:81ef392b7097d0474b5e1e19014b977a7b752f5e5cb86727f362127baf086102`，与报告和容器 `.Image` 一致；镜像为 `linux/amd64`、用户 `10001:10001`。容器及卷标签、挂载、资源限制与报告一致。当前容器为 `Running=false, ExitCode=1, OOMKilled=false, Pid=0`；带时间戳日志显示先前的 `ready` 和重启时的 `owned stop proof set incomplete or unexpected`。私有证据中的 kill 后及重启后标记均为十六进制 `64697274790a`，即 `dirty\n`；镜像内启动器副本与当前源码的 SHA-256 相等。
- `experiment-summary.json` 记载 kill 后退出码 137、`docker start` 命令退出码 0、TLS 校验及 SQL 写入和 kill 前读回成功，但没有保存脱敏的 SQL 请求/响应、查询结果哈希、逐步时间戳或原始 `docker wait`/`inspect` 输出。因此这些历史观察只能核对实验摘要，无法独立复算。当前 `inspect` 只能证实最终状态，不能反证或重建 kill 后的瞬时状态。
- 未采集本轮计划中的正常 TERM 对照和替代卷观测；重启后 SQL 读回因服务未启动而不可执行，报告对此已明确说明。

### 方法正确性：PARTIAL

- `SIGKILL` 后不修改原卷、直接启动同一容器，能回答“原卷无人工干预能否恢复服务”的窄问题。镜像 digest 固定，隔离卷、标签、回环端口和无自动重启设置也减少了外部干扰。
- 计划第 1 轮列出的干净 TERM 与异常 KILL、原卷与替代卷没有全部执行。正常 TERM 的既有发布验收不能代替同轮对照，因而不能把观察到的拒绝仅归因于 KILL，而排除环境或本次启动条件差异。仅有一次异常终止试验，也没有重复性估计。
- 可复现命令给出了主要参数和 SQL 助手，但不是实际执行脚本的完整记录；摘要缺少逐步原始输出。后续复现应在新隔离资源中记录命令、返回码、时间戳和脱敏 SQL 证据，不能重用或清理本轮保留的资源。

### 结论合理性：PASS

- 报告没有将 `docker start` 返回 0 当作业务恢复。其后进程退出码为 1，日志报 owned stop proof 错误，网关不可用，足以支持“本次原卷直接重启未恢复服务”。首次 `ready` 日志也被正确识别为旧事件。
- “安全拒绝通过、可用性未通过”准确限定了观察范围；dirty 标记与拒绝启动支持安全拒绝行为。报告没有由此推断数据丢失，也没有宣称 kill 后 SQL 写入已恢复，更没有把单宿主结果推广为多主机生产结论。
- 该结论不等于完整 v1.0.1 生产能力验收。尤其是备份恢复、RPO/RTO、自动接管和中断时间均无数据。

### 报告质量：PARTIAL

- 输入、隔离资源、步骤、结果、复现骨架和局限写得清楚，且报告只展示脱敏观察值。私有证据目录可追溯，未在文档中公开凭据。
- “原始输出摘要”实际混合了当前可复核事实与实验脚本写出的布尔摘要。建议对每个关键观察标注证据文件、命令输出及时间戳，并明确哪些是脚本断言、哪些是独立读取的状态。

## 关键问题与改进建议

1. **历史 SQL 与 kill 过程证据不够独立。** 在下一轮保留脱敏请求/响应记录或结果哈希、`docker kill`/`wait`/`inspect` 的原始退出码和时间戳，避免只依赖 `experiment-summary.json` 的布尔值。
2. **第 1 轮控制组缺失。** 用同一镜像和同样的隔离配置完成正常 TERM 对照，并明确是否仍需替代卷试验；记录差异，避免把不同轮次的发布验收直接作为本轮对照。
3. **完整成功标准尚未覆盖。** 后续隔离实验需分别验证有记录的备份恢复及新卷 SQL 读回、RPO/RTO，以及同一服务身份的自动接管、成功读写和中断时间。异常路径必须验证重启后业务就绪及确认写入读回，不能只看 Docker 命令返回码。
