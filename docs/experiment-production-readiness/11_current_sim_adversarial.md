# F08 提交镜像 S3 模拟：对抗审查

## 总结

**裁定：CONCLUSION_WEAKENED（限定范围内的观测结论成立）。** 四条路径的事件记录、驱动和脱敏日志相互吻合：干净重启读回成功；SIGKILL 后原卷启动失败；冷归档恢复 A、丢失备份后的 B；预建备用在本次约 60 秒探测窗内没有提供 SQL 服务。攻击集中在把本机指定 image ID 解释成可独立复现的提交构建、把脚本耗时解释成生产 RPO/RTO、把同宿主固定端口探测解释成 HA，以及把首次 stop proof 报错解释成完整故障因果。未发现足以推翻上述**狭义观测**的证据。

审查为只读；没有读取或输出凭据原值，没有操作 Docker。依据为 [`11_current_sim_report.md`](./11_current_sim_report.md)、[`11_current_sim_verification.md`](./11_current_sim_verification.md)、`/tmp/peri-current-sim-f08/` 中的脱敏事件、构建记录和驱动，以及仓库内被 DR 包装驱动调用的 `04_dr_driver.py`。

## 攻击结果

### 攻击 1：Go 缓存基底与构建上下文无法独立归因

- **目标结论**：本轮镜像可归因为提交 `45946d55ee94725dd8219fbe1fab991391f1459f` 的可复现产物。
- **攻击角度**：构建来源、遗漏输入、外部效度。
- **证据与替代解释**：标准构建因下载 `github.com/gorilla/websocket v1.5.3` 超时而失败；成功构建改用本地 `peri-go-cached:a7c9`。`go-cache-history.txt` 只显示复制了该模块缓存并设置 `GOPROXY=off`，不能证明复制内容的下载来源或字节完整性。镜像 ID、Dockerfile 哈希和编译日志能标识本机产物，却没有保存完整构建上下文或当时的 `git status` 原始输出。未归档的未跟踪文件、上下文内容或 BuildKit 缓存也是可能的输入。该缺口**不改变三项驱动实际调用该 image ID 的事实**，但削弱“指定提交构建”及供应链可追溯性。
- **严重程度**：严重，针对构建来源；对四项本机运行结果为中等。
- **建议修改**：将对象称为“使用所记录提交/tree、Dockerfile 和本地 Go 缓存基底构建、并由 image ID 固定的本机镜像”；保留构建前工作树干净仅为执行记录。不要把它写成发布镜像或独立复现的供应链证明。
- **可证伪方式**：保存构建前完整 `git status --porcelain=v1 -uall`、提交 checkout 与 `.dockerignore` 后的构建上下文清单及哈希；对 Go 基底做可信 digest 固定，记录缓存模块的 `.zip`/`.mod`/校验文件哈希和来源；在隔离干净 checkout 中无复用缓存重建，比较最终产物及关键输入哈希。仅复现相同 tag 不足以排除该攻击。

### 攻击 2：RPO/RTO 的端点比名称更窄

- **目标结论**：本轮 DR 的 RPO 为 `4.475s`，RTO 为 `3.386s`。
- **攻击角度**：时间定义和外部效度。
- **证据与替代解释**：`04_dr_driver.py` 在 A 的 SQL 回执**及读回之后**记 `ack_a_ns`，先后 KILL 并 wait 应用和 RustFS 后才记 `fault_ns`，恢复后 SQL 读回才记 `recovered_ns`。因此 `4.475s = fault_ns - ack_a_ns` 是“故障标记至最近已恢复写入读回完成”的代理年龄，略小于从 A 执行回执算起的年龄；`3.386s = recovered_ns - fault_ns` 是夹具完成故障注入后的恢复段耗时，不含故障检测和两次 KILL/wait。备份是一次人为安排的冷归档，B 在备份完成 `2.423s` 后获得确认且在恢复中丢失；这不能估算周期备份的最坏数据损失。报告已说明主要边界，但表格中简写“RPO/RTO”仍容易被当成运营指标。
- **严重程度**：严重，针对生产指标；对脚本算术为轻微。
- **建议修改**：在四项判定表中直接称为“本次脚本代理 RPO `4.475s`、恢复段 `3.386s`”，并注明 A 的采样在读回后、故障采样在两个 wait 后。不要把这些数值作为生产目标或上界。
- **可证伪方式**：记录 SQL execute 回执、备份可用时刻、真实服务故障首时刻、检测/宣告、恢复开始及同一客户端入口首次成功读回的单调时间；运行周期备份和随机时刻故障多轮实验，以预先定义的故障时刻计算 RPO、从故障发生至入口恢复计算 RTO，报告分布与最坏值。

### 攻击 3：HA 只覆盖同宿主进程 KILL 和一个夹具入口

- **目标结论**：预建备用的同卷接管能力失败，或由本次失败推定一般 HA 能力。
- **攻击角度**：故障隔离、入口与外部效度。
- **证据与替代解释**：`ha_current.py` 将两容器预建在同一 Docker 主机、网络、应用卷和 RustFS 桶上，备用容器在主进程退出后由同进程 watcher 执行 `docker start`。主/备配置都绑定同一个宿主回环端口；客户端继续使用原 TLS endpoint、CA 和项目 key。事件显示 watcher 已在 KILL 前就位，备用短暂 running、`docker start` 返回 0，随后退出 1、ready=0；56 次 SQL 探测均失败，末次距 KILL 返回 `60.083s`。这足以判定**该夹具路径未接管**。它没有注入宿主、卷、S3、网络或客户端路由故障，也没有验证旧主复活的 fencing；同宿主 watcher 和共享资源不能充当独立 HA 控制面。固定端口仅在旧容器退出后的顺序启动场景被覆盖；无法外推到跨宿主稳定入口。
- **严重程度**：严重，针对生产 HA 外推；对本次失败判定为轻微。
- **建议修改**：把结果固定为“本机共享卷/桶、旧主 KILL、watcher 顺序启动、固定回环端口的接管失败；56 个采样点不可用”。不要把 `docker start=0` 写成 ready，也不要据此单独定位入口故障或宣称完整 HA 失败模式已覆盖。
- **可证伪方式**：在独立故障域中部署主备与控制器，记录持续客户端入口的 DNS/代理/TLS 路由和首个恢复读回；分别注入宿主失联、网络分区、S3 不可达、旧主复活，并验证单写者 fencing、已确认数据及恢复时间。若本机夹具要隔离“入口”因素，应另做备用已 ready 后对其直接端点和原固定端点的同步探测。

### 攻击 4：stop proof 是首个门禁，尚不是完整因果证明

- **目标结论**：SIGKILL 后的 dirty marker 或 stop proof 缺失单独导致重启失败，且拒绝证明所有不安全状态都被排除。
- **攻击角度**：逻辑链、混淆变量。
- **证据与替代解释**：脏重启与 HA 备用日志都先报 `project stopped: owned stop proof set incomplete or unexpected`。`dev.py` 的 `verify_owned_stop_proofs` 在验证具体签名、worker incarnation 等之前先比较 `owned-proof` 目录文件集合；失败意味着这一检查未通过，后续可能存在其他独立拒绝条件。`dirty\n` marker 与 KILL 同时出现，但脚本没有单独操纵 marker 或 proof；不能估计任一因素单独的因果效应。反过来，错误信息与退出 1 已足以支持“本次安全启动拒绝”，无需推断数据损坏或恢复不可能。
- **严重程度**：中等；若把首个拒绝原因写成唯一根因则为严重。
- **建议修改**：沿用“首个可观察拒绝原因是 owned stop proof 集合不完整或含意外项；未验证 dirty marker 单独作用、后续门禁及数据可恢复性”。“安全拒绝生效”限于这两次启动尝试。
- **可证伪方式**：在隔离的复制卷上设计受控矩阵：clean/dirty marker、完整/缺失 stop proof、匹配/不匹配 worker incarnation 各自独立变化；逐组记录门禁顺序、退出码与 SQL 结果。不得在原始故障卷上改写 marker 或 proof 来制造恢复证据。

## 综合评估

| 攻击 | 严重程度 | 对结论的影响 |
| --- | --- | --- |
| Go 基底及上下文 provenance | 严重 | 本地 image ID 的行为成立；提交产物可独立归因的置信度降低 |
| DR 时间定义 | 严重 | 单次冷备份恢复成立；`4.475s`/`3.386s` 只能作脚本代理值 |
| HA 故障隔离与入口 | 严重 | 本机夹具接管失败成立；生产 HA 推断不成立 |
| stop proof 因果 | 中等 | 本次拒绝成立；唯一根因和后续门禁状态未证实 |

## 最终裁定

**CONCLUSION_WEAKENED。** 报告对生产 DR/HA 的限制基本正确，四项本机模拟结果可以保留。应进一步收紧构建来源、DR 指标表头、HA 适用范围和 stop proof 因果措辞。若后续要把这些结果用作生产验收，须补齐上述可证伪实验；现有证据不能支持该外推。
