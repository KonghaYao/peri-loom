# 挑战者验证清单（按风险优先级）

本目录独立于实现、现有压力工具和正式验收证据；这里只定义**待测场景**，没有执行记录，也不代表性能达标。目标是以生产相似但**隔离、可丢弃**的环境寻找数据错误、隔离失效、不可恢复的 Unknown、吞吐拐点和资源失控。先证明正确性，再逐级放大；一次只改变一个主要维度。每个场景先冻结版本、拓扑、数据生成种子、资源配额、负载曲线、阈值、采样和停止规则，不允许失败后改门槛重跑覆盖首次证据。

## 全部场景共用的验证合同

- 环境：独占的 Authority、至少两台 Worker、Controller、Gateway、Key Broker、独占 S3 兼容桶；真实 S3 仅给 Authority 凭据。TLS 验证不可关闭；私有密钥、`connection.json`、认证头不得进入报告。
- 基线：先拿到当前代码、构建产物、P0–P6 联合门禁及拓扑身份；用新的 namespace/project/branch 和独立数据种子。现有 `prototypes/v1/stress/README.md` 的联合 PASS、安全锁和预算是运行先决条件，不得用本文绕过。
- 正确性 oracle：由负载发生器在服务外保存预期主键/行 hash、事务 ledger（业务操作 ID）、账户总额、已确认提交集合；每阶段从**新会话**读取，独立比对 SQL 结果、数据库/分支身份及快照状态。已发送未确认写入标为 Unknown，不自动重试、不当作回滚；先查 durable ledger 再人工归类。
- 指标：按 project/DB/Worker 记录 offered、客户端丢弃、实际发送、ACK、typed 429、Unknown、错误、p50/p95/p99/max（成功和全部请求分开）、队列等待、活跃会话、CPU/RSS、磁盘、网络、对象存储请求/失败/延迟、root CAS 冲突、WAL/segment/checkpoint/GC（只记录实际暴露的指标）；保留原始时间戳和可核查的运行标识。没有观测接口的指标记 `NOT MEASURED`，不可推算成事实。
- 总停止条件：任何已确认写入丢失/重复、跨租户数据泄露、旧 epoch 写成功、无法归类的 Unknown、超预算或资源安全上限、夹具所有权/锁异常，立即停止**后续发压**，保留第一次失败现场；不得删桶、删锁、清 dirty marker 或直接杀共享进程。失败期间仅按批准的夹具合同收尾。
- 性能判定：阈值必须按目标机器和业务 SLO **测试前填写**，至少包含 ACK/s 下限、p95/p99 上限、错误/Unknown 上限、资源峰值、恢复时间、受害租户最小进展；未填写或未采样为 `NOT MEASURED`，不是 PASS。

## 按风险优先级排序的场景

排序依据：优先处理不可逆的数据损坏、越权和持久化错误，其次是恢复/隔离与事务语义，再处理容量和规模。**优先级不是执行许可**：缺联合门禁、安全夹具、独立 oracle 的场景记录 `SKIP`/`NOT MEASURED`，可先执行下一项可运行场景；P0 未验证不能宣称生产安全或性能 PASS。S 编号是稳定追踪 ID，左侧数字是当前优先级名次。

## 实施分界

- S01–S09 中已有测试/压力框架覆盖的部分可先运行**有限覆盖**；优先级高不代表这些场景必然已具备运行条件，是否实际可运行仍取决于联合 PASS、配置与夹具。`prototypes/v1/stress/README.md` 明确若干故障与快照交错场景是 SKIP。
- S10–S40 是对抗性扩展任务，不是可直接传给当前 runner 的 case 名称。S21–S29 来自上游数据库文档，S30–S40 来自 `challenger/ARCHITECTURE_RESEARCH.md` 的一手产品架构/事故资料；均属**风险启发**而不是本项目已存在该缺陷的断言。先补隔离夹具、故障注入契约、独立 oracle 与安全预算，再分别实施；不要将本文挑战档位混入已冻结 D05 矩阵或将共享机器结果写成生产性能 PASS。
- 每项产物至少包含：场景编号、版本/资源/数据种子/SQL 与流量模型、执行窗口、原始指标/ledger/hash、首次失败证据、Unknown 列表、清理及复核签名；结果统一为 `PASS`、`FAIL`、`SKIP`、`NOT MEASURED`，其中 `PASS` 仅指本场景预冻合同通过。
